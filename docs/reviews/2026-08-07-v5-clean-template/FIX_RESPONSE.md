# 阻断项修复回应

## 数学和输入

- 合同与模型统一为只接受 `[B, 577, D]`；无 CLS、无真实局部块或维度错误都会明确报错。
- 最终融合代码直接写成 `global_logits + 0.2 * local_logits`；配置为 0.3 时模型初始化失败。
- 新增受控 logits 评估测试：seen 类为 `[0, 2]`、unseen 类为 `[1, 3]`，实际得到 `S=1.0、U=0.5、H=2/3、ZS=1.0`。

## 模型和训练瘦身

- 删除 PSE 旧适配器、无几何 FGVD、SGMP 三路线、adapted 文本路线、缺 CLS 补平均值和复制 CLS 的路径。
- 删除未使用的 `class_attr`、`attr_text_embeds`、BVSA `cls_token`、重复 `weight_s2v`、未使用的 unseen 句子参数。
- 四份配置删除不生效或只负责切路线的字段，并继续保持逐字一致。
- 训练入口只加载单视角真实 CLS、576 个真实局部块、标签和 GPT-5.5 句子缓存；缺文件立即失败。
- 续训只允许命令行显式指定同一 `model/v5-template-v1` 产生的完整 checkpoint，不支持 auto、重启、微调或仅权重猜测。
- 新建 `tools/v5_evaluation.py`，正式 V5 不再调用共享 helper 里的 CLS 复制、在线提取、先验修正和偏置路线。

## checkpoint 转换安全

- 转换必须提供干净母版 `state_dict` 文件，目标字段不存在、形状或类型不一致都会失败。
- 历史字段与规范字段冲突时写 `status=failed` 收据，收据包含冲突目标和两个来源字段，不生成输出。
- 输出与收据使用 `xb` 独占新建，不再先检查后覆盖；写入失败只清理由本次成功创建的文件。
- 输入与目标清单一次读入内存并按读入字节计算 SHA-256，转换内容不会被中途路径变化偷换。

## 第二轮阻断修复

- 测试缓存改为训练启动时一次加载，后续 epoch 只复用内存张量；不再逐轮重新读盘。
- 训练、GPT-5.5、六份测试缓存、`res101.mat` 和 `att_splits.mat` 全部记录路径、SHA-256、大小；张量文件同时记录形状和类型。
- checkpoint 绑定准确代码 commit、完整配置与配置哈希、输入指纹、seen/unseen 顺序；任一不一致都拒绝续训。
- checkpoint 保存并恢复 Python、NumPy、Torch CPU 与全部 CUDA RNG；新增小模型连续训练和中断续训逐步零差异测试。
- 转换器异常路径不再执行任何 `unlink`。即使收据写入失败且输出路径被并发替换，也不会删除并发者文件。

## 第三轮边界阻断修复

- 所有正式输入先计算一次 SHA-256 和大小，再加载到内存，加载完成后重新计算；两次不一致就停止，因此记录的指纹不会与训练实际读到的张量错位。
- 新增可重复触发的替换测试：先读入旧张量，再替换磁盘文件，加载后检查会明确拒绝继续。
- 正式 V5 训练移除旧 `CUBDataLoader`，改用 43 行的最小 xlsa17 划分读取器；它只读 `res101.mat` 与 `att_splits.mat`，并逐项核对三份缓存标签顺序，不再依赖未使用的 `clip_att/CUB_attribute.pkl`。
- Torch CPU RNG 和各 CUDA RNG 状态恢复前都会显式 `.cpu()`；CPU 上用真实中断恢复测试逐 step 比较 loss、全部参数和学习率，CUDA 行为由源码合同测试锁住。当前机器没有 CUDA，真实 GPU 恢复仍需服务器运行时再确认。

修复后决定：进入全工作流机器验证和原三名审核人复审；尚不冻结、训练或推送。
