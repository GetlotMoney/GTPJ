# V5 干净代码母版行为合同

## 1. 这份文件锁定什么

这份合同用于把历史 V5 中真正有效的计算路径重新提取为干净母版。清理可以删除旧名字、旧兼容层和后续实验开关，但不能悄悄改变模型输入、类别顺序、最终分数、训练损失或 GZSL 评估含义。

历史只读参照如下：

- Git Tag：`v5`
- Git commit：`08e5ecb1a5db6c6d589527cda35d8d4f7f437e07`
- 模型参照：`model/MyModel.py`
- 训练与评估参照：`train_GTPJ_CUB.py`
- 参数参照：`config/versions/v5.yaml`

历史 Tag 和上述 commit 永远不移动；新母版用新的 commit 和 Tag 表示，不覆盖旧历史。

## 2. 正式输入

V5 的正式训练和评估输入是 `clip_features`：

- 常规形状为 `[B（本批图片数量）, 577（1 个 CLS 全局标记 + 576 个图像块）, 768（CLIP 特征维度）]`；
- 第 0 个位置是 CLS 全局特征，后 576 个位置是按原顺序排列的局部图像块；
- 正式训练数据流使用 `float32`，允许训练入口在 CUDA 上按现有策略临时使用 `bfloat16` 自动混合精度，但不得改变张量的样本顺序和位置含义；
- 为保持历史输入接口，模型仍接受 `[B, 576, 768]`、`[B, 1, 768]` 或 `[B, 768]`。这些情况沿用原实现：缺少 CLS 时取局部块平均作为全局特征，只有一个或没有显式局部块时把现有特征扩展成 576 个位置。

`seenclass` 和 `unseenclass` 保存数据集里的全局类别编号。二者的编号、顺序和训练标签映射都遵循 `standard_v1`：训练输出按 `seenclass` 顺序取列，评估输出保持全部 200 个 CUB 类别的全局列顺序。

## 3. 必须保留的计算模块

干净 V5 只保留以下正式模块：

1. PSE（渐进语义增强）：适配类别文本，并对句子级文本做自注意力聚合；
2. FGVD（频率引导视觉解耦）：按当前 `v2_abs_mean` 规则选择局部图像块，并使用几何编码；
3. BVSA（双向视觉—语义对齐）：同时计算“语义找视觉”和“视觉找语义”两路局部分数；
4. ICSA（图像条件语义适配）：用当前图片的 CLS 特征修正 seen 类文本；
5. SGMP（语义引导掩码预测）：产生 MPP 掩码预测损失和负语义约束损失；
6. 全局分支与局部分支的固定加法融合。

动态路由、可学习融合门、旧 AG-JEPA/LastViT/FAE 名称镜像，以及只为旧 checkpoint 占位的无效参数，都不属于 V5 母版。旧 checkpoint 如需继续使用，必须先经过独立转换工具生成新文件和转换收据，不能把兼容分支重新塞回模型。

## 4. 分数和输出

规范配置固定为：

```text
score_mode = add
local_weight = 0.2
final_logits = global_logits + 0.2 * local_logits
```

这里 `global_logits` 是 CLS 全局图像特征与类别文本的相似度，`local_logits` 是 BVSA 输出的局部对齐分数。局部分支权重 0.2 是固定配置值，不按样本或类别动态变化。

训练时 `forward(..., is_train=True)` 的 `logits` / `clip_S_pp` 形状为 `[B（本批图片数量）, C_seen（训练可见类别数量）]`，类别列顺序与 `seenclass` 完全一致。

评估时 `forward(..., is_train=False)` 的 `logits` / `clip_S_pp` 形状为 `[B（本批图片数量）, 200（CUB 全部类别）]`，类别列使用全局类别编号。内部输出可以统一改用 PSE、FGVD、BVSA、ICSA、SGMP 的规范名称，但训练和评估直接依赖的公开字段必须保持可用。

## 5. 损失和评估含义

V5 保留以下损失：交叉熵、全局/局部一致性、文本拓扑、BMDD 双向分布约束、SGMP 的 MPP 损失和负语义损失。删除旧字段名时，损失的数学表达、权重、梯度流向和 detach 位置不得变化。

数据和评估继续使用 CUB 的 xlsa17 `att_splits.mat`，并锁定以下含义：

- U：unseen 测试集上的逐类 GZSL 准确率；
- S：seen 测试集上的逐类 GZSL 准确率；
- H：`2 * U * S / (U + S)`；
- ZS：只在 unseen 类别列中预测得到的逐类准确率。

上述四项共同对应 `gzsl_u_s_h_zs_v1`，不能因代码瘦身改变 split、类别顺序、标签映射、偏置处理或最佳 checkpoint 选择规则。

## 6. 本地等价验证边界

清理前后使用同一组 CPU 固定小输入、相同随机种子和相同有效权重对照。最终 logits、各项损失和关键梯度采用 `rtol=1e-5`、`atol=1e-6`；形状、类别列和输出字段采用完全一致检查。

这个本地对照只能证明代码路径在给定输入上等价，不能冒充服务器精度结论。U/S/H/ZS 是否保持不变，仍需用户当前明确授权后在服务器用正式数据和相同训练条件复跑确认。
