# V5 局部分支消融结果同步与下一批实验启动计划

## 要解决的问题

`V5-ABLATION-001` 已在实验分支完成，但 `main` 仍把它写成“计划中”。如果直接合并实验分支，会把专属训练代码、控制器和测试带入正式模板管理分支；如果不回填，GitHub 又无法作为可信的实验总账入口。

## 已核实的事实

- 冻结母版是 `MODEL-V5-TEMPLATE-V1@2f5fa5e631ef82658d4bac587cdfd17f3534cb35`；
- FULL 与 GLOBAL_ONLY 各完成 seed 5、17、29，平均 H 分别为 `74.11` 与 `74.03`，配对平均差值为 `+0.08`；
- 三条差值为 `+0.25/-0.09/+0.09`，不能写成稳定 H 增益；
- 训练后 strict-3 审核已通过；原始运行证据在 Warehouse，Git 只保留轻量账本与哈希；
- 当前本地 `main` 比 `origin/main` 多 119 个提交，推送尚未得到 owner 授权。

## 本次最小实现

1. 从 `main` 建立结果同步分支，只同步状态、参数矩阵、结果、质量检查、配置快照和审核证据；
2. 修正 `FRAMEWORK_TREE.md` 与证据索引中遗留的“待运行”说法；
3. 机器校验账本、母版绑定、参数矩阵和仓库边界；
4. 本地合入 `main` 前先完成只读复核。是否推送到 GitHub 仍由 owner 单独决定。

## 下一批实验的边界

新的实验都从 `model/v5-template-v1` 独立分叉，不在 `main` 或 `framework/v5` 上直接训练。优先建立：PSE、ICSA 和纯 CLIP 基线；FGVD、SGMP、辅助损失与拓扑损失分别作为独立问题，不把多个开关堆进同一实验。

每项进入正式训练前都必须完成：代码级唯一变量检查、参数矩阵、独立审核、pre-run freeze、干净工作树和运行前门检查。局部分支整体已经有结论，后续局部子模块实验只用于解释内部抵消或支撑论文明确声明的贡献。

## 验收与回退

- 验收：`main` 的所有索引都把 `V5-ABLATION-001` 记为 completed，并能回指参数、结果、审核和 Warehouse 证据；不出现训练代码或大文件。
- 回退：结果同步是独立提交；回退该提交不会影响原实验分支、Warehouse 证据、冻结模板或任何历史失败记录。
