# 02 — 框架全景图

> 这一篇回答：数据从哪来、经过哪些模块、最终到哪去。不纠结代码细节，只看大局。

## 1. 一句话总结 GTPJ

**用冻结的 CLIP 提取图像和文本特征，然后通过可训练的模块增强这些特征，最后用增强后的特征做 GZSL 分类。**

## 3. 为什么是这个结构？— 三个问题驱动的设计

### 问题 1：CLIP 文本太粗糙

CLIP 的文本编码器把 "一只蓝色冠蓝鸦站在树枝上" 编码成一个 768 维向量。但如果每个类别有 7 句不同的描述（强调颜色、栖息地、体型……），直接取平均就丢失了句子间的差异。

**→ PSE 解决**：用自注意力让 7 个句子互相增强，再和原始平均做残差混合。

### 问题 2：CLIP 视觉太全局

CLIP 的 CLS token 是整张图的全局总结。但细粒度鸟类识别需要看翅膀纹路、喙的形状——这些是局部信息，全局 token 里被平均掉了。

**→ FGVD + BVSA 解决**：从 576 个 patch 里选出 32 个关键 patch，用几何感知编码后，和文本做跨模态对齐，得到局部分数。

### 问题 3：文本原型对所有图像都一样

不管图像里的鸟是站着、飞着、还是逆光剪影，文本原型都是同一个。这是不合理的——不同图像应该对应不同的语义侧重。

**→ ICSA + Conditional BVSA 解决**：用当前图像的 CLS token 产生一个微小偏移（只有 0.8%！），让文本原型变成"这张图专属"，并且全局和局部两个分支共享同一套条件文本。

## 4. 关键参数一览

| 参数 | 值 | 作用 |
|---|---|---|
| `batch_size` | 64 | 每步训练用多少张图 |
| `dim_f_clip` | 768 | CLIP ViT-L/14 的特征维度 |
| `tf_common_dim` | 512 | BVSA Transformer 内部的隐藏维度（768→512 降维） |
| `fgvd_select_k` | 32 | 从 576 个 patch 中选多少个（576→32 大幅筛选） |
| `pse_outer_ratio` | 0.65 | PSE 增强后的文本和原始文本的混合比例 |
| `icsa_ratio` | 0.008 | 图像条件注入的比例（非常小！不到 1%） |
| `local_weight` | 0.2 | 局部分数在最终分数中的权重 |
| `weight_s2v` | 0.5 | S2V 和 V2S 两个方向的混合比例 |

## 5. 训练 vs 评估的区别

| | 训练 | 评估 |
|---|---|---|
| 输入文本 | all_text_cond [B, C, 768] | all_text_cond [B, C, 768] |
| 分数 | S_final [B, C] → slice 到 [B, 150] | S_final [B, C] 全 200 类 |
| 损失 | CE + 5 个辅助损失 | 无 |
| Dropout | 生效 | 关闭 |
| 梯度 | 计算 | 不计算（`torch.no_grad()`） |

## 6. 从 CLIP 基线到 v5 的进化

```
CLIP 零样本         ~60 H
    │
    ├─ +PSE(瓶颈层) + FGVD + BVSA + ICSA + SGMP
    │
    ▼
GTPJ v1           73.93 H  (+14)
    │
    ├─ PSE 从瓶颈层升级为自注意力
    ▼
GTPJ v2           74.29 H  (+0.36)
    │
    ├─ SGMP 上下文升级为 FAE main-memory（严格条件模式）
    ▼
GTPJ v3           74.47 H  (+0.18) ← 当前 confirmed 最强基线
    │
    ├─ BVSA 文本输入改为条件文本 (bvsa_text_mode=conditional)
    ▼
GTPJ v5           74.44 H  (repeat mean) ← 当前 active mainline
```
