# 实现说明

## 改动目标

恢复老 V5 与干净 V5 在同一个随机种子下的模型初始化位置，同时继续保持干净模板没有
无效参数、没有兼容开关、没有额外前向分支。

## 实际改动

在 `model/MyModel.py` 的 BVSA 构造函数中，紧跟历史上两个无用投影层原来的位置，调用
`_consume_historical_v5_projection_initialization(dim_com, dim_f)`。

该函数只做四件事：

1. 临时创建一个 `Linear(dim_com, dim_f)`；
2. 再临时创建一个同尺寸 `Linear(dim_com, dim_f)`；
3. 让 PyTorch 按历史顺序完成它们的默认随机初始化；
4. 立即释放两个局部对象，不把它们挂到任何 `nn.Module` 上。

## 比较过的三种办法

| 办法 | 好处 | 问题 | 决定 |
|---|---|---|---|
| 永久恢复两个旧层 | 最直观地复刻旧代码 | 无用参数进入优化器和 checkpoint，代码重新变脏 | 不采用 |
| 临时创建后丢弃 | 精确恢复随机序列，不污染模型 | 需要注释说明为什么存在 | 采用 |
| 立刻重构为每模块独立随机数生成器 | 长期隔离性最好 | 会改变历史训练身份，改动范围过大 | 留作未来新模板设计，不在本确认实验做 |

## 边界

- 本次只改实验分支，不改 `model/v5-template-v1` Tag 指向的冻结提交。
- 不新增配置开关；否则每次实验都会继续堆兼容分支。
- 不修改数据加载、前向、损失、评估和训练入口。
- 是否形成新模板版本，必须等 GPU 确认结果和单独接纳决定。

## 测试方法

测试先在修复前运行并失败，准确列出 SGMP/ICSA 初始权重不一致；修复后同一测试转为通过。
测试同时检查全部活跃状态、模型创建后的随机状态、连续三次批次抽样，以及正式模型中不存在
两个历史无用层。

实验目录另提供 `verify_seed_equivalence.py`。它使用真实 `512→768` 尺寸，从固定历史提交
`4b259379...` 直接读取老模型，并输出活跃状态、CPU/CUDA RNG、前三批索引、参数数量和配置哈希。
正式模式必须传入准确候选提交，同时要求工作树干净、分支正确、模型与配置 Git blob 未被替换。
