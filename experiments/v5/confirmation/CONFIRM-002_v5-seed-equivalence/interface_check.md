# 接口与科学口径检查

## 结论

本次没有改变模型输入、输出、损失、数据划分或评估定义。唯一有意变化是：修复版 V5 在模型
创建结束后，CPU 随机状态重新与老 V5 对齐，从而让同 seed 的后续训练批次和活跃模块初值一致。

## 逐项检查

| 检查项 | 修复前后 | 说明 |
|---|---|---|
| 输入张量 | 不变 | `[B（图片数量）, 577（全局+局部块数量）, 768（特征维度）]` |
| 输出 logits | 不变 | `[B（图片数量）, 200（类别数量）]` |
| 最终分数 | 不变 | `global_logits + 0.2 × local_logits` |
| 活跃模块 | 不变 | PSE、FGVD、BVSA、SGMP、ICSA |
| 损失 | 不变 | CE、consistency、topology、BMDD、MPP、negative 及总损失 |
| 模型参数名和数量 | 不变 | 没有注册 `proj_visual`、`proj_text` |
| checkpoint | 不变 | `state_dict` 不包含两个历史无用层 |
| 配置文件 | 不变 | 继续使用冻结的 V5 参数 |
| 数据与类别顺序 | 不变 | CUB xlsa17 `standard_v1` |
| U/S/H/ZS 口径 | 不变 | 仍由受保护 V5 evaluator 计算 |
| CPU 随机状态 | 有意改变 | 从干净模板的错位状态恢复到老 V5 的历史状态 |
| 同 seed 批次顺序 | 有意改变 | 恢复为老 V5 的 `torch.randperm` 顺序 |

## 尚未覆盖

本地零训练测试不能代替正式 CUDA 训练。服务器零步指纹和 5 次 GPU 复现完成前，不能声称
精度已经恢复，也不能据此更新正式 V5 模板或框架 Tag。
