# 新旧 V5 配置等价说明

## 为什么不能把老配置原样喂给今天代码

老 V5 配置包含很多旧别名和兼容开关，例如 `use_fae`、`use_clip_a_self`、`lambda_jepa`。今天的瘦身模板已经删除这些重复入口，并且会拒绝未知字段。如果强行修改今天代码让它接受旧字段，就不再是在验证“今天实际使用的代码”。

因此本实验采用两份各自原样的配置：

- 老 V5：`configs/V5-069.yaml`，SHA-256 为 `a11706a...62aca`；
- 今天模板：`configs/CURRENT-V5.yaml`，SHA-256 为 `def1d44c...b9e`。

## 如何证明有效参数相同

自动测试会把两份 YAML 的 `value` 解包，再逐项检查今天配置的所有字段都存在于老配置且值完全相同。学习率三段只删除老代码专用的 `restart_from_best: false` 兼容字段，`lr`、`epochs` 和 `eta_min` 不变。

| 今天模板参数 | 老 V5 对应值 | 处理 |
|---|---|---|
| `pse_heads/dropout/inner_ratio/outer_ratio` | 同名字段 | 原值保留 |
| `weight_s2v=0.5`、`local_weight=0.2` | 同名字段 | 原值保留 |
| `fgvd_select_k=32` | 同名字段 | 原值保留 |
| `lambda_consist/topo/bmdd/mpp/neg` | 同名字段 | 原值保留 |
| `icsa_ratio=0.008`、`icsa_hidden=48` | 同名字段 | 原值保留 |
| `sgmp_topk=8`、`sgmp_hidden=512` | 同名字段 | 原值保留 |
| 三段学习率与总计 50 epoch | 同名字段 | 仅删除无效兼容键 |

老配置多出的字段分为三类：旧名字的同义重复、今天模板已经固定开启的 V5 路径、今天模板已经删除且不参与 V5 最终行为的历史兼容字段。它们没有被替换成别的数值。

## 结论边界

这项检查能证明“今天配置是老 V5 有效参数的瘦身投影”，不能代替服务器精度对跑。只有老代码和今天代码在本轮五次结果分布中对齐，才能说迁移没有造成可见精度损失。
